# 同济2025计算机夏令营面试备考指南

原文：[https://www.yuque.com/bandaotiehe-gexb9/hsldt8/fzdqfk1giwwho95l](<https://www.yuque.com/bandaotiehe-gexb9/hsldt8/fzdqfk1giwwho95l>)

# **一、面试概况**

## **1.1 考核分值构成**

同济大学计算机夏令营总成绩350分，面试占比最高，是决定优营排名的关键：

| **考核环节** | **分值** | **占比** | **时间** |
| --- | --- | --- | --- |
| 机试 | 40分 | 11.4% | 2小时，2道OJ题 |
| 专业课笔试 | 60分 | 17.1% | 60分钟，选择+大题 |
| 英语笔试 | 50分 | 14.3% | 30分钟，阅读+翻译 |
| 英语口试 | 50分 | 14.3% | 含在面试中 |
| 综合面试 | 150分 | 42.9% | 约15分钟/人 |

**综合面试150分占比最大，是拉分核心。笔试和机试难度适中，面试才是拉开差距的环节。**

## **1.2 面试流程与形式**

1. 面试按方向分组，每组5位老师轮流提问，含一位固定的英语提问老师。
2. 5-6分钟PPT自我介绍（所有后续问题均围绕PPT和简历展开）。
3. 英语问答（1-2个问题，可能是日常问题或专业问题）。
4. 思政/综合素质问题（1个左右，如中国精神、社会实践）。
5. 专业/项目提问（多位老师轮番提问，是面试主体，可能有压力面）。

不同小组问法差异较大：有的组纯项目拷打不问专业课，有的组会问408专业课，有的组英文问科研项目。你报考的导师通常会在你的面试考场。

## **1.3 面试特点与注意事项**

- 问题全部围绕PPT和简历，务必对自己写的每一个项目、每一个技术点都能深入展开。
- 老师可能会发散追问，从一个项目细节延伸到底层原理，需要扎实的技术功底。
- 整体老师态度友好，但会有压力面（连续追问、质疑），要保持冷静。
- 优营率很高（约75%），但排名影响学硕/专硕和导师选择，仍需认真对待。
- 建议在同济面试前先参加一个其他营的面试“练手”，适应线下面试节奏。

# **二、PPT自我介绍策略（5-6分钟）**

## **2.1 PPT内容框架**

| **模块** | **时长建议** | **内容要点** |
| --- | --- | --- |
| 基本信息 | 30秒 | 姓名、本科院校、专业、排名、英语成绩 |
| 科研经历 | 2-2.5分钟 | 重点讲1-2个核心项目：问题、方法、你的贡献、实验结果 |
| 竞赛/工程 | 1分钟 | 挑含金量高的，突出技术能力和成果 |
| 学生工作/思政 | 30秒 | 简要带过，但可能成为思政提问来源 |
| 研究生规划 | 30秒 | 为什么选同济、感兴趣的方向、读博意愿 |

## **2.2 关键原则**

1. PPT是提问的“地图”，你写上去的每一个技术名词都可能被追问。不要写自己不懂的东西。
2. 科研项目讲清楚“动机→方法→实验→结论”，重点突出你个人的贡献和创新点。
3. 技术名词要有“防御纵深”：提到一个算法，要能讲清原理、公式、优缺点、改进方向。
4. 适当“埋点”：在PPT中有意放置自己熟悉且准备充分的技术点，引导老师提问。
5. 控制时间，不要超时。提前反复演练，确保5-6分钟内讲完。

\*\*【面试提示】\*\*面试老师手里有你的简历和报名表，PPT不需要罗列所有信息，重点讲亮点和故事。自我介绍的核心目的是“引导老师在你准备好的领域提问”。

参考回答：竞赛给我三方面收获。一是技术上，将课堂知识应用到实际问题中，比如在XX竞赛中我负责XX模块，深入理解了XX技术；二是团队协作，学会了在压力下分工配合、高效沟通；三是解决问题的能力，竞赛中遇到XX困难，通过查阅文献、反复实验最终解决，这种能力对科研同样重要。

\*\*【答题思路】\*\*辩证看待+个人倾向+与同济的匹配。

## **4.3 专业类英语问题**

**Can you explain what word embedding is?**

**【参考答案】**

Word embedding is a technique that maps discrete words into dense,
continuous, low-dimensional vectors. Unlike one-hot encoding, which
represents each word as a sparse high-dimensional vector, word
embeddings capture semantic relationships between words. For example,
words with similar meanings are close to each other in the vector
space, and we can observe relationships like
'vector(king) - vector(man) + vector(woman) ≈ vector(queen)'.
Common methods include Word2Vec, GloVe, and now contextual embeddings
like BERT. Word embeddings are fundamental inputs for neural NLP models.

\*\*【面试提示】\*\*专业英语面试的关键不是语法完美，而是能用简单准确的语言把技术概念讲清楚。建议提前准备自己科研项目的英文介绍（2-3分钟版本），以及核心技术名词的英文解释。

## **4.4 英语面试备考建议**

1. 准备30秒和2分钟两个版本的英文自我介绍。
2. 准备常见日常问题的回答模板（为什么同济、介绍家乡、未来规划、兴趣爱好）。
3. 准备科研项目的英文介绍：项目背景、你的方法、实验结果、你的贡献。
4. 熟悉自己研究方向的核心术语英文表达（如word embedding, fine-tuning, multimodal fusion等）。
5. 听不懂时可以礼貌请求重复：“Sorry, could you please rephrase the question?”，不要冷场。

# **五、专业技术问题详解与参考答案**

以下问题均来自2025年同济CS夏令营面试真实回忆。每题给出题目背景、知识点讲解和参考回答，回答时注意控制在1-2分钟内，先给结论再展开，老师追问时再深入细节。

## **5.1 指令流水线中的数据相关及解决方法**

【真题】**请你讲讲什么是数据相关，pipeline怎么解决数据相关的？**

### **知识点讲解**

数据相关（Data Hazard）是指在指令流水线中，后续指令需要使用前面指令尚未写回寄存器堆的结果，导致数据依赖冲突。以经典五级流水线（IF→ID→EX→MEM→WB）为例，一条指令的结果在WB阶段才写回寄存器堆，但后续指令可能在ID阶段就读寄存器，产生时间差。

**三种数据相关类型：**

| **类型** | **全称** | **含义** | **出现场景** |
| --- | --- | --- | --- |
| RAW | Read After Write（写后读） | 后一条指令要读前一条指令还未写回的数据 | 最常见，真数据相关 |
| WAR | Write After Read（读后写） | 后一条指令写寄存器时，前一条还未读完 | 乱序执行/多发射时出现 |
| WAW | Write After Write（写后写） | 两条指令写同一寄存器，写回顺序错误 | 乱序执行时出现 |

在简单的五级顺序流水线中，主要遇到的是RAW相关。

**解决方法：**

1. 数据旁路（转发/Bypassing/Forwarding）：将ALU计算结果从EX/MEM或MEM/WB流水线寄存器直接转发到下一条指令的ALU输入端，不需要等待写回寄存器堆。这是最常用的硬件解决方法，可以解决大部分RAW相关。
2. 流水线停顿（Stall/插入气泡）：当数据转发也无法解决时（典型是load-use冒险：lw指令后紧跟使用该数据的指令，因为lw的数据在MEM阶段结束才产生，而下一条指令在EX阶段就需要），硬件检测到冒险后插入一个停顿周期（气泡），等待数据可用。
3. 编译器指令调度：编译器在相关指令之间插入不相关的独立指令，填充等待槽，避免流水线停顿。
4. 寄存器重命名：通过硬件寄存器重命名消除WAR和WAW相关（假相关），主要用于乱序执行处理器。

### **参考回答**

数据相关是指流水线中后续指令需要前面指令尚未写回的结果。最常见的是RAW写后读相关。解决方法主要有三种：第一是数据旁路，也叫转发，把ALU的计算结果直接从流水线寄存器转发给下一条指令的ALU输入，不需要等写回；第二是插入停顿，当转发也解决不了时，比如load-use冒险，lw下一条指令要用这个数据，硬件会插入一个气泡等一个周期；第三是编译器调度，在相关指令之间插入无关指令来填充等待槽。对于乱序执行处理器，还会用寄存器重命名来消除WAR和WAW假相关。

\*\*【面试提示】\*\*面试时建议主动提到load-use冒险这个具体例子，体现理解深度。老师可能追问：“转发能解决所有RAW吗？”答案是不能，load-use冒险需要stall+转发配合。

## **5.2 CPU分支问题（控制冒险）的解决**

【真题】**请你讲讲怎么解决CPU分支问题？（该问题针对面试者的硬件项目）**

### **知识点讲解**

分支问题（控制冒险/Control Hazard）是指分支指令（条件分支beq/bne、跳转j/jal等）改变程序执行流，导致流水线中已经预取的后续指令可能无效。在五级流水线中，分支指令在ID阶段才完成比较和目标地址计算，但此时后续一条指令已经取指，如果分支发生，这条预取的指令就是错误的。

**解决方法：**

1. 停顿/冻结流水线：最简单的方法，在分支指令后插入停顿直到分支结果确定，但会损失2-3个周期，性能差。
2. 分支预测（Branch Prediction）：

- 静态预测：编译器或硬件固定预测。包括总是预测不跳转、总是预测跳转、BTFN（向后跳转预测发生，因为循环通常向后跳）。实现简单但准确率有限。
- 动态预测：运行时根据历史信息预测。主要技术包括：分支历史表BHT（记录最近一次是否跳转，1位/2位饱和计数器）、分支目标缓冲BTB（缓存分支目标地址）、两级自适应预测器（用全局/局部历史模式索引模式历史表）、锦标赛预测器（组合多个预测器，选择最准的）。

3. 延迟分支（Delayed Branch）：MIPS等架构采用，由编译器在分支延迟槽中放入有用指令（如分支前的不相关指令），填充流水线等待时间。
4. 推测执行（Speculative Execution）：沿预测方向继续取指执行，保留现场，若预测正确则提交结果，预测错误则回滚刷新流水线。现代高性能CPU普遍采用。

**预测错误的代价：**

预测错误时需要清空流水线中错误路径上的指令，重新从正确地址取指，代价等于流水线深度（约15-20个周期在现代CPU上）。因此高预测准确率（通常\>95%）对性能至关重要。

### **参考回答**

CPU分支问题就是控制冒险，分支指令会改变PC，导致流水线中已经预取的指令可能无效。解决方法主要有四类：第一是简单停顿，等分支结果确定，但性能损失大；第二是分支预测，分静态预测和动态预测，静态的比如总是预测不跳转或BTFN，动态的用分支历史表和饱和计数器根据历史预测，现代处理器还用两级自适应预测器和锦标赛预测器；第三是延迟分支，MIPS架构用的，编译器在延迟槽放有用指令；第四是推测执行，预测后继续执行，错了就回滚。预测错误的代价是清空流水线，所以预测准确率很关键，现代CPU能达到95%以上。

\*\*【面试提示】\*\*如果被追问“2位饱和计数器为什么比1位好”：1位计数器在循环退出时会连续错两次（一次改变方向，一次改回来），2位计数器需要连续两次错才改变预测方向，对偶发的分支方向变化更鲁棒。

## **5.3 MCTS（蒙特卡洛树搜索）算法**

**【真题】请你介绍MCTS算法。（针对面试者的软件项目）**

### **知识点讲解**

MCTS（Monte Carlo Tree Search，蒙特卡洛树搜索）是一种用于决策问题的启发式搜索算法，通过随机模拟来评估搜索树中各状态的价值，在巨大搜索空间中高效找到最优决策。AlphaGo是MCTS最著名的应用。

**核心数据结构：**

搜索树中每个节点代表一个状态，边代表动作。每个节点维护两个统计量：N(v)（该节点被访问次数）和Q(v)（该节点的累计收益/价值估计）。

**四个核心步骤（每次迭代）：**

1. 选择（Selection）：从根节点开始，根据树策略（Tree Policy）递归选择子节点，直到到达一个未充分展开的叶节点。最常用的选择策略是UCB1（Upper Confidence Bound）：

UCB1(v) = Q(v) / N(v) + C \* sqrt(ln N(parent) / N(v))

第一项是利用（Exploitation）：选择平均收益高的节点
第二项是探索（Exploration）：优先选择访问次数少的节点
C是探索常数，平衡探索与利用

1. 扩展（Expansion）：如果叶节点不是终局状态且访问次数达到阈值，则创建一个或多个子节点加入搜索树。
2. 模拟（Simulation/Rollout）：从新扩展的节点开始，用默认策略（Default Policy，通常是随机选择动作）快速模拟到终局，得到一个胜负结果（奖励值）。
3. 反向传播（Backpropagation）：将模拟结果沿选择路径从叶节点回传到根节点，更新路径上所有节点的N(v)和Q(v)。

迭代结束后，选择根节点下访问次数最多（或平均收益最高）的子节点对应的动作为最终决策。

**MCTS的优点：**

- 不需要领域知识的启发式评估函数（纯随机rollout即可工作）
- 非对称搜索：自动集中搜索更有希望的分支，适合巨大分支因子的问题
- 计算时间可控：任意时间算法，随时可以停止并返回当前最优解

**MCTS的局限：**

- 纯随机rollout可能不够准确，需要结合价值网络（如AlphaGo用深度神经网络引导选择和评估）
- 在分支因子极大或稀疏奖励问题中收敛较慢

### **参考回答**

MCTS是蒙特卡洛树搜索，通过随机模拟来评估搜索树中状态的价值。每次迭代分四步：第一步选择，从根节点用UCB1公式选择子节点到叶节点，UCB1平衡利用和探索，一项是平均收益，一项是访问次数的平方根项；第二步扩展，给叶节点加子节点；第三步模拟，从新节点随机走到终局得到结果；第四步反向传播，把结果沿路径更新所有节点的访问次数和收益。多次迭代后选访问次数最多的子节点动作。它的优点是不需要启发式评估函数、搜索非对称、随时可停。AlphaGo把MCTS和深度神经网络结合，用策略网络引导选择、价值网络评估局面，效果非常好。

## **5.4 多模态融合存在的问题**

**【真题】请你说说多模态融合存在哪些问题？**

### **知识点讲解**

多模态融合是指将文本、图像、音频、视频等不同模态的信息进行有效整合以完成下游任务。当前主要面临以下问题：

1. 模态异质性鸿沟：不同模态的数据形式、分布、维度和信息密度差异巨大。文本是离散符号序列，图像是连续像素张量，音频是时序信号，难以直接在同一空间中比较和融合。
2. 语义对齐困难：不同模态中对应同一语义的信息表达方式不同，如何建立细粒度的跨模态对应关系（如图像区域与词语的对齐）是核心难题。
3. 模态缺失与噪声：实际场景中某些模态可能不可用或质量差（如图像模糊、语音含噪），模型需要鲁棒地处理模态缺失和噪声干扰。
4. 融合策略选择：早期融合（特征级拼接）、晚期融合（决策级投票/加权）和混合融合各有优劣，如何针对任务选择最优策略没有统一答案。
5. 负迁移问题：不同模态可能包含冲突或无关信息，简单融合可能导致模态间互相干扰，反而降低性能。
6. 数据对齐成本高：高质量的配对多模态训练数据（如图文对、视频字幕）获取和标注成本高昂。
7. 计算资源消耗大：多模态模型通常参数量巨大（如CLIP、GPT-4V），训练和推理成本高。
8. 模态权重自适应：不同模态对不同样本的贡献不同，如何动态调整各模态的融合权重是一个开放问题。

### **参考回答**

多模态融合主要有几个层面的问题。第一是模态异质性，文本、图像、音频的数据形式和分布差异很大，很难直接融合；第二是语义对齐，怎么建立不同模态之间细粒度的语义对应关系；第三是模态缺失和噪声，实际场景中某些模态可能不可用或质量差；第四是融合策略，早期融合、晚期融合、混合融合各有优劣，怎么选；第五是负迁移，模态间可能有冲突信息导致互相干扰；另外还有配对数据标注成本高、模型计算量大、模态权重怎么动态调整等问题。

## **5.5 多模态融合研究与实际应用的难点差异**

**【真题】你觉得多模态融合和多模态的实际应用相比，有哪些难点？**

### **知识点讲解**

这个问题考查对学术研究与工程落地之间gap的理解。可以从以下角度对比：

| **维度** | **研究层面的难点** | **实际应用的难点** |
| --- | --- | --- |
| 核心目标 | 提升benchmark精度、提出新融合机制 | 稳定性、实时性、成本、用户体验 |
| 数据 | 使用公开标注数据集，质量可控 | 真实数据噪声大、分布偏移、标注缺失 |
| 模态可靠性 | 假设各模态输入完整可靠 | 模态可能缺失、延迟、质量动态变化 |
| 计算约束 | GPU集群训练，不太关心推理成本 | 端侧部署、延迟要求、算力受限 |
| 泛化能力 | 在标准数据集上验证 | 跨域、跨场景、跨语言泛化 |
| 评估标准 | 准确率、F1等定量指标 | 用户满意度、容错性、可解释性 |
| 安全伦理 | 较少关注 | 隐私保护、内容安全、偏见公平 |

### **参考回答**

我认为研究和应用的侧重点不同。研究层面主要关注怎么设计更好的融合架构来提升精度，比如跨模态注意力机制、对比学习策略，数据通常是公开数据集，质量有保证。但实际应用中有额外的难点：一是真实场景数据噪声大、有分布偏移，模型可能不work；二是模态可能动态缺失，比如摄像头被遮挡或麦克风断连，模型要能优雅降级；三是计算约束，端侧部署要求低延迟和低功耗，大模型可能跑不动；四是泛化性，实验室数据集上效果好不一定在真实场景好用；五是工程层面的稳定性、可维护性和用户体验，这些在论文里不太关注但落地时很关键。

## **5.6 词嵌入（Word Embedding）的作用**

**【真题】请你说说你怎么理解词嵌入的作用的？**

### **知识点讲解**

词嵌入是将自然语言中的词语映射为低维、稠密、连续的实数向量的技术。它是现代NLP的基础表示方法。

**词嵌入解决的核心问题：**

1. 维度灾难：传统one-hot编码词向量维度等于词表大小（数万到数百万），且极度稀疏。词嵌入将维度压缩到100-768维，大幅降低计算量。
2. 语义鸿沟：one-hot中任意两个词向量正交，无法表达语义相似性。词嵌入使语义相近的词在向量空间中距离相近（如“猫”和“狗”比“猫”和“汽车”更近）。
3. 语义关系编码：词嵌入能编码词之间的线性关系，如经典示例 vec(king) - vec(man) + vec(woman) ≈ vec(queen)，以及 vec(北京) - vec(中国) ≈ vec(东京) - vec(日本)。
4. 泛化能力：稠密向量使模型能将一个词上学到的信息泛化到语义相近的词，缓解未登录词（OOV）和数据稀疏问题。
5. 可计算性：词向量可以进行加减、距离计算、聚类等数学运算，支持语义相似度计算、类比推理等下游应用。

**发展脉络：**

- 静态词嵌入：Word2Vec（CBOW/Skip-gram）、GloVe、FastText，每个词对应一个固定向量。
- 动态词嵌入：ELMo、BERT、GPT等上下文相关模型，同一个词在不同语境下有不同向量表示，解决多义词问题。

### **参考回答**

词嵌入的作用是把离散的词映射成低维连续向量。传统one-hot编码有两个问题：一是维度太高，词表多大向量就多长；二是任意两个词向量都正交，表达不了语义关系。词嵌入解决了这两个问题：它把词压缩到几百维的稠密向量，而且语义相近的词在向量空间里距离近，比如“猫”和“狗”会比较近。更重要的是它能编码语义关系，比如king减man加woman约等于queen。这样模型就能捕捉词之间的语义关联，也有更好的泛化能力。从Word2Vec到BERT，词嵌入从静态发展到动态，能根据上下文给同一个词不同的向量，解决了多义词问题。

## **5.7 文本与图像特征如何对齐**

**【真题】请你讲讲文本和图像的特征如何对齐？**

### **知识点讲解**

图文特征对齐是多模态学习的核心问题，目标是让不同模态的特征在共享语义空间中可比较、可检索。主要技术路线如下：

**1. 共享嵌入空间 + 双塔结构**

用两个独立的编码器分别提取图像和文本特征，将它们映射到同一维度的共享向量空间，通过对比学习拉近配对图文的距离、推远不配对的距离。代表工作是CLIP：图像编码器（ResNet/ViT）和文本编码器（Transformer）分别编码，InfoNCE对比损失在批次内将匹配的图文对作为正样本、其余为负样本。

InfoNCE Loss:
L = -log \[ exp(sim(I,T)/τ) / Σ exp(sim(I,T\_i)/τ) \]
其中 sim(I,T) = I·T / (|I||T|) 为余弦相似度，τ为温度系数

**2. 跨模态注意力机制（Cross-Attention）**

在Transformer架构中，用一个模态的特征作为Query，另一个模态的特征作为Key和Value进行注意力计算，实现细粒度的跨模态交互。代表工作包括ViLBERT、LXMERT、BLIP等。Cross-attention能建模图像区域与文本词之间的细粒度对应关系。

**3. 预训练任务驱动对齐**

- 图文对比（ITC）：CLIP式对比学习，对齐全局语义。
- 图文匹配（ITM）：二分类预测图文是否匹配，细粒度对齐。
- 掩码语言建模（MLM）：根据图像和部分文本预测被mask的词。
- 掩码区域建模（MRM/PatchMIM）：根据文本和部分图像预测被mask的图像区域。
- 词-区域对齐（Word-Region Alignment）：如UNITER通过最优传输实现显式细粒度对齐。

**4. 融合架构分类**

| **架构类型** | **特点** | **代表模型** |
| --- | --- | --- |
| 双塔结构 | 两个编码器独立编码，只在最后计算相似度，效率高 | CLIP、ALIGN |
| 单塔融合结构 | 图文拼接后输入Transformer深度交互，精度高但效率低 | ViLBERT、LXMERT、BLIP |
| 混合结构 | 双塔检索+单塔精排，兼顾效率和精度 | ALBEF、BLIP-2 |

### **参考回答**

图文特征对齐主要有几种方式。最经典的是双塔结构，用图像编码器和文本编码器分别提取特征，映射到共享空间，通过对比学习让匹配的图文向量靠近、不匹配的推远，CLIP就是这个思路，用InfoNCE损失。第二种是跨模态注意力，用一个模态做Query另一个做Key和Value做cross-attention，实现细粒度交互，ViLBERT、LXMERT用的这种。第三种是通过预训练任务来驱动对齐，比如图文对比、图文匹配、掩码语言建模等。架构上分双塔、单塔融合和混合三种，双塔效率高适合检索，单塔融合深精度高适合复杂推理，混合结构兼顾两者。

\*\*【面试提示】\*\*如果被追问“CLIP为什么用对比学习而不是直接预测”，可以提到：ImageNet式的固定类别标签限制了模型的泛化能力，对比学习利用大规模噪声图文对进行度量学习，让模型学到开放词汇的语义表示，zero-shot能力强。

## **5.8 计算机组成原理与系统结构的联系与区别**

**【真题】谈谈计算机组成原理和系统结构的联系与区别？**

### **知识点讲解**

计算机系统结构（Computer Architecture）和计算机组成原理（Computer Organization）是计算机科学中两个紧密相关但层次不同的概念。

**1. 经典定义（Amdahl, 1964）**

计算机系统结构是程序员所看到的计算机系统的属性，即概念性结构与功能特性，包括指令集架构（ISA）、数据类型、寻址方式、寄存器组织、存储编址、I/O机制等。这些属性对程序员可见，决定了程序如何与机器交互。

计算机组成是计算机系统结构的逻辑实现，包括数据通路结构、控制器设计、流水线组织、Cache层次、总线设计、乘法器实现等。这些对程序员透明，决定了架构如何具体实现。

**2. 联系**

- 系统结构是“做什么”（接口规范），组成是“怎么做”（具体实现）。
- 同一系统结构可以有不同组成实现。例如x86架构有Intel和AMD不同实现，ARM架构有Cortex-A78和Cortex-X2不同微架构。
- 组成技术的发展会影响系统结构的设计。例如Cache的出现影响了存储层次架构，多核技术推动了并行指令和内存模型的演进。
- 两者共同决定计算机系统的性能、功耗和成本。

**3. 区别**

| **维度** | **计算机系统结构** | **计算机组成原理** |
| --- | --- | --- |
| 研究层面 | 程序员可见的系统属性（ISA层） | 架构的硬件实现（微架构层） |
| 核心问题 | 指令集设计、并行系统、存储模型、性能评价 | 数据通路、控制器、流水线、Cache、总线 |
| 设计目标 | 定义软硬件接口，提供可编程性 | 在约束下高效实现架构 |
| 举例 | x86/ARM/RISC-V指令集、寻址方式 | 五级流水线、Tomasulo算法、组相联Cache |
| 变化频率 | 相对稳定，需要向后兼容 | 随工艺和应用需求快速迭代 |

**4. 现代理解**

现代“计算机系统结构”的范围已经扩展，不仅包括ISA，还包括微体系结构、存储系统、互连网络、并行计算（多核、GPU、TPU）、异构计算、能效优化等。计算机组成原理更侧重单处理器内部的基本结构和工作原理，是系统结构的先修基础。

### **参考回答**

计算机组成原理和系统结构是两个层次。按Amdahl的经典定义，系统结构是程序员可见的属性，也就是指令集架构，包括指令集、寻址方式、寄存器、数据类型这些，它定义了软硬件接口；组成原理是这些属性的具体硬件实现，比如数据通路怎么设计、流水线怎么组织、Cache怎么做。两者联系紧密：同一架构可以有不同组成，比如x86有Intel和AMD的不同实现；组成技术的发展也会推动架构演进，比如多核推动了并行模型。区别上，组成关注“怎么实现”，比如五级流水线、Tomasulo算法；系统结构关注“怎么设计更好的系统”，比如ISA设计、GPU架构、并行计算。可以说组成是系统结构的基础，系统结构是组成的上层抽象。

## **5.9 LoRA微调原理**

**【真题】介绍一下LoRA微调的原理？**

### **知识点讲解**

LoRA（Low-Rank Adaptation，低秩适配）是一种参数高效微调方法（PEFT），由Hu等人于2021年提出，用于在不修改预训练模型权重的情况下高效适配下游任务。

**1. 核心思想**

预训练模型在下游任务微调时，权重的更新量ΔW具有低秩特性——即权重变化主要发生在低维子空间中。LoRA不直接更新原始权重W∈R^{d×d}，而是在旁边增加一个低秩分解的旁路：

W' = W + ΔW = W + B·A

其中 W ∈ R^{d×d} 冻结不训练
 A ∈ R^{r×d} 通过高斯随机初始化
 B ∈ R^{d×r} 初始化为零矩阵
 r \<\< d 为秩（如 r=8, 16, 64）

前向传播：h = W·x + B·A·x

**2. 参数量分析**

原始全量微调需要更新d×d个参数。LoRA只需要训练A和B两个矩阵，参数量为2×r×d。当r=8、d=4096时，参数量从约1670万减少到约6.5万，压缩比超过250倍。

**3. 为什么B初始化为零**

训练开始时ΔW=B·A=0（因为B为零矩阵），保证训练从原始预训练模型出发，训练过程稳定。

**4. LoRA的优点**

1. 参数量和显存大幅减少，降低微调硬件门槛。
2. 推理无额外开销：训练完成后可以将B·A合并到W中，即W\_new=W+BA，推理时与原模型完全相同，无延迟增加。
3. 模块化：可以为不同任务训练不同的LoRA权重，切换任务时只需替换小的LoRA矩阵。
4. 可插拔：LoRA模块可以方便地加载和卸载，不影响原始模型。

**5. LoRA通常加在哪些层**

LoRA最初论文只加在Transformer的Attention层的Q和V投影矩阵上。实践中也可以加在K、O、FFN层上，加的层越多表达能力越强但参数量也增加。QLoRA进一步将量化与LoRA结合，实现单卡微调大模型。

### **参考回答**

LoRA是低秩适配，一种参数高效微调方法。它的核心假设是大模型微调时权重变化是低秩的。具体做法是冻结预训练权重W，在旁边加两个小矩阵A和B，把权重更新分解成ΔW=B乘A，其中A是r乘d，B是d乘r，r远小于d。训练时只更新A和B，参数量从d平方降到2rd，大大减少显存和计算量。A用高斯初始化，B初始化为零，保证训练从原模型出发。LoRA的一个重要优点是推理时可以把BA合并回W，没有额外推理开销。另外不同任务可以训练不同的LoRA权重，切换方便。LoRA通常加在Attention的Q、V投影矩阵上，QLoRA还结合了4位量化。

\*\*【面试提示】\*\*可能追问：“LoRA和全量微调相比效果如何？”答案是在很多任务上LoRA能接近甚至匹配全量微调效果，尤其是r选择合适时；但在需要大量新知识或复杂任务上，全量微调可能更优。

# **六、项目与简历面答题方法**

## **6.1 项目提问的一般模式**

同济面试的项目提问是主体，5位老师轮流提问，常见模式：

1. 动机类：为什么做这个项目？要解决什么问题？
2. 方法类：你用了什么方法？为什么选这个方法？有没有试过其他方法？
3. 细节类：这个模块具体怎么实现的？这个参数怎么调的？这个公式什么意思？
4. 实验类：实验怎么设计的？基线有哪些？指标为什么选这个？结果为什么好/不好？
5. 延伸类：这个方法有什么局限？如果让你改进你会怎么做？这个技术和XX有什么区别？
6. 贡献类：这个项目中你个人做了什么？（多人项目必问）

## **6.2 项目回答框架**

**推荐使用“问题-方法-细节-结果-反思”五步法回答项目问题：**

| **环节** | **内容** | **时长** |
| --- | --- | --- |
| 问题 | 项目背景、要解决的核心问题、挑战 | 20秒 |
| 方法 | 整体方案、技术路线、为什么选这个方案 | 40秒 |
| 细节 | 你的具体工作、关键技术点、创新点 | 40秒 |
| 结果 | 实验数据、对比结果、 ablation | 20秒 |
| 反思 | 局限性、改进方向、收获 | 20秒 |

## **6.3 真题与答题要点**

【真题】说说科研项目的实验怎么开展的？

**【答题要点】**

- 先明确实验目的：验证什么假设？回答什么研究问题？
- 数据集：用了什么数据集，规模多大，为什么选它，怎么划分train/val/test。
- 基线方法：选了哪些对比方法，为什么选这些（覆盖经典和SOTA）。
- 评价指标：用什么指标衡量，为什么选这个指标。
- 实验环境：硬件、框架、超参数设置。
- Ablation Study：各模块的贡献分析，证明每个设计的必要性。
- 结果分析：不仅报数字，还要分析为什么好/不好，误差分析。

【真题】介绍一下你发的专利保护内容是什么？

**【答题要点】**

专利问题要讲清楚：技术领域→要解决的问题→技术方案的核心创新点（与现有技术的区别）→有益效果。不要念专利全文，用通俗语言讲清楚“你的方法新在哪里、解决了什么问题”。老师关注的是你的创新能力和对技术方案的理解。

## **6.4 项目面注意事项**

- PPT上每个技术名词都要能展开讲至少3层深度（是什么→为什么→细节/改进）。
- 不要夸大自己的贡献，多人项目明确说明自己负责的部分。
- 不会的问题诚实说“这个我没有深入研究过，但我了解大概是……”，不要瞎编。
- 老师质疑或指出问题时不要争辩，先肯定老师的观点再解释你的思考。
- 准备一个“最得意的项目”和一个“踩坑经历”，前者展示能力，后者展示成长。

# **七、面试准备清单与建议**

## **7.1 面试前准备清单**

| **类别** | **准备事项** | **优先级** |
| --- | --- | --- |
| PPT | 5-6分钟版本，反复演练计时，找同学模拟提问 | ★★★★★ |
| 项目 | 每个项目准备2分钟/5分钟两个版本，梳理技术细节和可能追问 | ★★★★★ |
| 专业课 | 复习408高频概念（数据结构、OS、计组、网络），特别是PPT涉及的方向 | ★★★★ |
| 英语 | 自我介绍、日常问题、项目英文介绍、专业术语 | ★★★★ |
| 思政 | 准备中国精神、科技报国、学术诚信等主题的个人化回答 | ★★★ |
| 院校了解 | 了解同济CS方向、感兴趣导师的研究方向 | ★★★ |
| 行为问题 | 为什么同济、读不读博、其他营情况、未来规划 | ★★★ |
| 物料 | 简历多份、PPT备份（U盘+邮箱）、纸笔 | ★★★ |

## **7.2 面试中的表现建议**

1. 语速适中，不要赶。5分钟PPT讲完比讲不完好。
2. 回答问题先给结论再展开，用“第一、第二、第三”让老师抓住要点。
3. 不会就坦诚说，不要硬编。老师都是专家，瞎编很容易被看穿。
4. 被追问到不会的深度时，可以说“这个方向我了解不深，但根据我的理解……”，展示推理过程。
5. 保持和所有老师的眼神交流，不要只看提问的老师。
6. 面试结束时可以表达感谢和对同济的向往，但不要过度奉承。

## **7.3 结合笔试的备考建议**

笔试和面试是连续两天，建议提前两周开始准备：

- 前10天：专业课复习（算法设计与分析、数据结构、操作系统分页）+ 项目梳理 + PPT制作。
- 中间5天：PPT演练 + 英语准备 + 模拟面试（找同学互相提问）。
- 最后3天：机试保持手感（做几道模拟题）+ 笔试错题回顾 + 面试状态调整。
- 同济包食宿，提前一天到嘉定校区熟悉环境，保证睡眠。

\*\*【面试提示】\*\*多位学长学姐建议：在同济面试前先参加一个其他学校的夏令营面试“垫手”，线下面试的紧张感需要真实体验来适应。
